# Редизайн всего сайта texspeckps.ru

Дата: 2026-09-24. Продолжение спецификации главной
(`2026-09-24-pk-homepage-design.md`) — её визуальный язык, токены, анимации,
переключатели темы/языка и защита от стилей Tilda переиспользуются без изменений.

## Цель

Все страницы сайта в стилистике новой главной: стильно, дорого, представительно.
Кейсы — главное доказательство навыков, поэтому переработаны сильнее всего:
разделены, переписаны, с упором на количество, внешний вид и функционал.

## Страницы (13 блоков T123)

| URL | Назначение |

| `/faq` | Виджет ИИ-ассистента Salebot + статический список вопросов для SEO |

почта, hh.ru), выбор темы/языка сохраняется между страницами (`localStorage`).

## Архитектура

```
src/
  base.css            токены, reset, компоненты (из главной)
  base.js             тема, язык, меню, reveal, счётчики, спотлайт, магнит
  partials/header.html, footer.html
  i18n/common.en.json словарь шапки/подвала/общих строк
  pages/<slug>.html   разметка страницы (+ <slug>.en.json, <slug>.css/.js при нужде)
  data/cases.json     все кейсы (RU+EN)
build.js              Node, без зависимостей: собирает dist/<slug>.html
admin/admin.html      локальная админка кейсов
dist/                 готовые блоки для T123
```

- Сборка: `node build.js` → для каждой страницы: meta viewport + шрифты +
  `<style>`(base + страница) + `.pk-root`(header + page + footer) + JSON-LD +
  `<script>`(словарь EN страницы, base.js, скрипт страницы).
- Словарь EN склеивается из `common.en.json` + словаря страницы.
- Страницы кейсов генерируются из `cases.json` одним шаблоном.
- `index` (главная) переносится в систему: итог визуально идентичен текущему
  `tilda-block.html`.

## Кейсы

### Честность контента

Придуманные проценты роста (+64%, −41% и т. п.) **не переносятся**. Вместо них:

- **Факты-метрики** — то, что видно в проекте: число экранов, категорий,
  сценариев, этапов, «24/7», «запись из CRM».
- **Итог словами** — что изменилось для клиента, без выдуманных измерений.
- **Метка статуса**: «Реальный проект» или «Концепт». По умолчанию —
  «Реальный проект», если есть клиент/живой сайт; «Концепт» для учебных.
  Павел правит метку в админке.

### Схема данных (`cases.json`)

```json

  "dir": "tilda",                 // salebot | tilda | figma | getcourse

  "year": 2026,
  "title": { "ru": "MAXFIT", "en": "MAXFIT" },
  "lead": { "ru": "…", "en": "…" },
  "cover": "https://static.tildacdn.com/…",
  "url": "https://fitbasepro.ru/",          // живой сайт, опционально
  "facts": [ { "v": "5", "l": { "ru": "этапов пути", "en": "journey stages" } } ],
  "task": { "ru": "…", "en": "…" },
  "flow": [ { "t": { "ru": "…", "en": "…" }, "d": { "ru": "…", "en": "…" } } ],
  "done": [ { "ru": "…", "en": "…" } ],
  "result": { "title": {…}, "text": {…} },
  "tools": ["Tilda", "Zero Block"],
  "gallery": [ { "src": "…", "cap": { "ru": "…", "en": "…" } } ]

```

### Витрина направления

- Hero направления: название, короткий позиционирующий текст, число кейсов,
  стек.
- Фильтр по типу (напр. «Лендинги / Многостраничные / Магазины» для Tilda;
  «Воронки / ИИ-ассистенты / Игровые механики» для Salebot).
- Сетка карточек: обложка (первый скриншот), тип, год, метка статуса, название,
  одна строка сути, 2 факта. Hover — лёгкий зум обложки и спотлайт.
- Переход к другим направлениям и финальный CTA.

### Полноэкранный кейс

- Открывается поверх витрины, URL-якорь `#<id>` (ссылка делится, «назад» в
  браузере закрывает кейс). Весь текст кейсов — в HTML страницы (индексируется).
- Структура: шапка кейса (тип · год · статус, название, лид, кнопка «Открыть
  сайт») → полоса фактов → Задача → Сценарий/путь (горизонтальная схема шагов,
  как на главной) → Что сделал (чек-лист) → Галерея (крупные скриншоты,
  полноэкранный лайтбокс со стрелками/свайпом/Esc) → Итог → Инструменты →
  навигация «← предыдущий / следующий →» + CTA «Хочу так же» → `/form`.
- Доступность: `role="dialog"`, `aria-modal`, фокус внутри, Esc закрывает,
  возврат фокуса на карточку, блокировка прокрутки фона.

### Тексты кейсов

Переписываются в едином голосе: коротко, по делу, от первого лица, без
канцелярита («разработал чат-бота, который…» → «Бот продаёт доступ в канал и
сам следит за сроком подписки»). Опечатки исправляются («ТОЧКА ОПОРА» →
«ТОЧКА ОПОРЫ», дубли шагов «04, 04» → 04, 05, «SalesBot» → «Salebot»).

## Админка кейсов (`admin/admin.html`)

- Локальный файл, не публикуется — доступ только у Павла.
- Открывается двойным кликом в браузере; работает офлайн (кроме превью картинок).
- Загружает текущий `cases.json` (выбор файла) или стартует с встроенной копии.
- Список кейсов с фильтром по направлению; добавить / редактировать / удалить /
  поменять порядок.
- Форма со всеми полями схемы, RU и EN рядом; динамические списки (факты, шаги,
  «что сделал», галерея, инструменты).
- Живое превью карточки и кейса в стиле сайта.
- Кнопки: «Сохранить cases.json» (скачивание файла), «Скопировать код страницы
  <направление>» — генерирует готовый блок T123 (тот же шаблон, что `build.js`)
  прямо в браузере и кладёт в буфер обмена.
- Картинки: Павел загружает их в Tilda (или любой хостинг) и вставляет ссылки;
  в админке — поле URL с превью.
- Черновик автосохраняется в `localStorage` браузера.

## Форма (`/form`)

Механика старой страницы сохраняется: чипы направления, поля внутри текста
письма, живой предпросмотр, валидация имени и контакта, отправка через
Telegram Bot API, «Скопировать текст». По решению Павла отправка остаётся
прямой через бота (токен в коде страницы — риск принят владельцем).
Добавлено: предвыбор направления по `?service=`, состояния отправки
(загрузка/успех/ошибка), ссылки на все мессенджеры.

## i18n

EN-перевод для всех страниц и кейсов. Исключение — текст политики
конфиденциальности: на EN показывается пометка, что документ действует на
русском. Внутренние ссылки ведут на те же страницы (сайт двуязычный целиком,
пометка «RU» больше не нужна и удаляется).

## SEO

- На каждой странице один H1, семантические секции, JSON-LD по типу страницы
  (`CollectionPage`/`CreativeWork` для кейсов, `OfferCatalog` для прайса,
  `FAQPage` для FAQ, `ProfilePage` для резюме).
- `SEO.md` дополняется title/description/OG для каждой страницы.

## Проверка

- `node build.js` без ошибок; 13 файлов в `dist/`.
- Каждая страница: 375 / 768 / 1440 px, обе темы, оба языка, нет горизонтального
  скролла, консоль чистая, нет русских строк в EN (кроме текста политики).
- Кейсы: открытие по клику и по прямой ссылке `#id`, Esc/назад закрывают,
  лайтбокс листается, фокус возвращается.
- Форма: предпросмотр обновляется, валидация, `?service=` предвыбирает чип
  (отправку проверяю на тестовом перехвате `fetch`, без реальной отправки).
- Админка: добавленный кейс появляется в превью и в сгенерированном коде.
- Эмуляция `#allrecords a { color }` Tilda не ломает цвета.
